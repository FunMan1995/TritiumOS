HAL opcode structure (close to RISC-V structure)
b0     +)
b1     m)
b2     8b) => 8-bit if set
b3     dir)
b4     &)
b5     i)
b6     16b) => 32-bit if set, 16-bit if unset
b11:7  rd (destination register)
b14:12 Zeroes (funct 3)
b19:15 rs1 (source register)
b24:20 rs2 (no meaning in HAL, but can temporarily hold a value)
b25    signed)
b27:26 Zeroes
b31:28 hbank index

See [hw/riscv] for general register assignment. There, it says that x10-x12 are
for temporary HAL variables. To avoid stepping on each other toes, here are
the policies for those registers:

x10: immediate loading, either from i) m) or +)
x11: source value "staging" register
x12: carry flag and other uses that dont fit x10 or x11

=) <>) <) >=) etc..
  b2:0 correspond to funct3, but b3 is special and handled by "brc," before
  orring the condition in. This bit indicates that we should swap rs1 and rs2.

loadstore, ( instr off op -- )
  Assuming that "off" fits in 12-bit, write the load/store instruction based on
  base instruction "instr" and depending on whether "op" has HALINV (load if no,
  store if yes).

@, ( op -- )
  One of the complexities here is the "big offset" case, a fetch with HALOFF not
  fitting in 12-bit. In that case, we load the offset in x11, add the source
  register to it, then use x11 as a base register for the load/store.

?imm, ( op -- op )
  Checks if operand is i) or m). If it is, compile a write of this value to x10
  and modify operand in consequence

mvreg, ( op -- )
  Write a move from operand's src to operand *dereferenced* dst.
  If operand has an offset, use add/addi'rs2 to add the offset to dst.
  Store offset in x10 if it does not fit in 12 bits.

  00000013 addi) xZERO rd) xZERO rs1) 0 imm)
  00000033 add) xZERO rd) xZERO rs1) xZERO rs2)

regZ ( instr -- r )
  Get the register to be used as the Z flag.
  Depending on the operand type, this fetches the rd, rs1, or rs2 field.

preari, ( op1 instr -- op1 instr op2 )
  Prepares the arithmetic instruction for a call to "op," or alternatives.
  This handles indirect source and destination (e.g. m) dir)) and load them in
  x11. op2 is the modified operand to be written while op1 is the original.
  op2 will always be direct and never immediate.

  Immediate handling:
  if instr & $fe00000 != 0 || immediate > 12 bits
    load immediate into x10
    change op to use x10
  else
    store immediate into instr
    change instr's opcode from OP to OP-IMM

?x11>src, ( op -- )
  If op is indirect and dir), store x11 to its source.

ari, ( op instr -- )
  Write inverted arithmetic operation, that is:
  1. Load operand's src in x11
  2. Apply instr with x11 as Rd and Rs1 and operand's dst as Rs2.
  3. Store x11 in operand's src

swap-, ( op -- )
  The setting of b31 is *not* part of RISC-V. It's an internal flag we set for
  swapping rs1 and rs2 later on.

?signed ( op cond -- op cond )
  Transform the condition into a signed one if the operand is signed.

?rs1<>rs2 ( cond op -- cond op )
  Swap the two registers depending on cond's 3 bit. As described in the cond
  words note above.

?src>x11, ( op -- op )
  Load the value of the register to x11 if the op is indirect and mangle the
  bits so x11 is the new source. If not, make the operand "dyadic", that is:
  move rs1 to rs2 and copy rd to rs1.

bcc12, ( op cond -- )
  Create a conditional branch instruction that jumps to 12 bytes forward.
  Store an immediate or dereference a register to x11 if needed.

  00000663 beq) xZERO rs1) xZERO rs2) 12 imm)

?>12b ( n -- f )
  Return a non-zero result if the given signed number does *not* fit in 12bits.

  40b25213 srai) xW rdrs1) 11 imm)
  00120213 addi) xW rdrs1) 1 imm)
  ffe27213 andi) xW rdrs1) -2 imm)

  Due to sign extension, the last operation is equivalent to 1 invand.

shift, ( op instr -- )
  Embed the high bits of the instruction into the immediate number so it can be
  processed by ari,. This is because the immediates in shift are only 5-bit
  wide and the function (e.g. srai) is encoded in the higher 7 bits.

?swapreg ( instr op -- instr op )
  Swap the two source registers in the final instruction if bit 32 is set. This
  is used for swap-.

+n, ( n operand -- )
  Use x12 as a staging register for the value to be added to.
  A value of 0 is handled differently to only generate a load/move.

?rs1>x10, ( op -- op )
  Maybe move rs1 to x10 in the context of a le@, or be@, op.

  If op's rs1 is the same as rd or if HALOFF is set, compile a move of that
  register to x10 and set rs1 to x10.

remdiv, ( op instr -- )
  A special case of op, to handle the signedness and direction of the special
  /mod, operation. We cannot use ari, because it only supports operations with
  two operands. On the other hand instructions produced by /mod, use three
  operands.

/mod, ( op -- )
  In order for microarchitectures to fuse both the remainder and division into
  a single divide operation, it is recommended to order these as follow:

  div[u] rdq, rs1, rs2
  rem[u] rdr, rs1, rs2

  Where rdq is neither rs1 or rs2. To achieve this order, the /mod, operation
  uses x12 as rdq and xS as rdr (as required by the HAL). Then x12 is saved into
  the original destination.

lrot, ( op -- )
  As rotation isn't supported in the core extension of RISC-V, it is emulated
  through the following definition:
  lrot(x, n) = ((x << n) | (x >> (sz - n)) & MASK
  Where sz is the size of the destination operand and is only different in the
  case of 16b) dir) or 8b) dir). The mask only matters in those cases but is
  automatically performed by the store operation.

  The following relation is used in the code to save instructions:
  "(x & (sz-1)) - sz" is equivalent to "x | (-sz)"

  00005593 srli) x11 rd) xZERO rs1) 0 imm)
  00006513 ori) x10 rd) xZERO rs1) 0 imm)
  40a00533 sub) x10 rd) xZERO rs1) x10 rs2)
  00a05633 srl) x12 rd) xZERO rs1) x10 rs2)
  00001033 sll) xZERO rd) xZERO rs1) xZERO rs2)
  00c06033 or) xZERO rd) xZERO rs1) x12 rs2)

rrot, ( op -- )
  The same logic applies, but reversed. Machine code not documented here is
  documented at lrot,.

  00001593 slli) x11 rd) xZERO rs1) 0 imm)
  00a01633 srl) x12 rd) xZERO rs1) x10 rs2)
  00005033 sll) xZERO rd) xZERO rs1) xZERO rs2)

C>x12, ( op -- )
  This word is defined in [arch/riscv/hal/instr.fs].
  Due to RISC-V's unique ability to not have any flag, we must emulate add with
  carry and substract with carry through a temporary register which is x12.
  A carry/borrow is generated if the result is smaller than its source.

  00003633 sltu) x12 rd) x0 rs1) x0 rs2)

+-x12, ( instr op -- op )
  This word is defined in [arch/riscv/hal/instr.fs].
  Adds or substracts x12 to op's destination depending on instr.
  
  Due to the significant complexity it would require to handle immediate
  properly, these are always loaded in x10 when dealing with carries.
