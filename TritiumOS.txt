2. CORE MANDATE (USER-DICTATED PROPERTIES)
--------------------------------------------------------------------------------

TritiumOS is built **in Forth** and **utilizes a pure mathematical algorithm**
to **refine intelligence into Forth** — executable words, definitions, and
labeled structures — not into opaque weight tensors. User terms: *noliage
refinement* (refined knowledge foliage); *labeling* / **labeled neural groups**;
**neural linking data** between groups and neurons.

No opaque ML weight blobs as the source of truth; intelligence is **derived,
extracted, refined, and emitted as Forth** through explicit math.

Two engines define the cognitive substrate:

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  D.R.E.N.A.                                                             │
  │  Dynamic Recursive Evolving Neural Architecture                         │
  │  — Constructs each neuron and the evolving graph topology               │
  └───────────────────────────────┬─────────────────────────────────────────┘
                                  │ raw / evolving neuron fabric
                                  ▼
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  R.E.K.I.A.                                                             │
  │  Artificially Intelligent Knowledge Extraction and Refinement           │
  │  — Pure-math refinement engine; refines on-demand intelligence per      │
  │    neuron when queried or activated                                     │
  └───────────────────────────────┬─────────────────────────────────────────┘
                                  │ refined knowledge (on demand)
                                  ▼
              Personal assistant (S0) → shell / services → L.I.N.E.O.S. (S3)

**Division of labor**

  D.R.E.N.A.  →  *structure*  (birth, growth, recursion, connection policy)
  R.E.K.I.A.  →  *semantics*  (extract, refine → **Forth output** + labels)
  D.R.E.N.A.  →  *topology*   (neural groups, **neural linking data**)

Every neuron’s on-demand intelligence is **constructed by D.R.E.N.A.** and
**refined by R.E.K.I.A.** into **Forth** at activation time (lazy refinement).
Neurons belong to **labeled neural groups**; **neural linking data** records
edges, weights, and address-fold maps between neurons and groups.

3. NEURON ENCODING — FIRST FOUR 4-BIT SECTIONS
--------------------------------------------------------------------------------

Each neuron begins with a fixed **16-bit header** (= 4 sections × 4 bits).
Sections are numbered S0..S3 (low to high address or Forth field order — pick
one in implementation and document in `docs/NEURON.md`).

### 3.1 Trit pairs in S0, S1, S2

Each of the first three sections holds one **trit pair** (two trits):

  Section   Bits   Content
  ───────   ────   ─────────────────────────────────────
  S0        4      trit pair A = (t0, t1)   each ti ∈ {-1,0,+1}
  S1        4      trit pair B = (t2, t3)
  S2        4      trit pair C = (t4, t5)

**4-bit section → trit pair mapping (canonical — implement in Forth word
`trit-pair@`):**

  A 4-bit nibble value n ∈ [0..15] maps to (t_lo, t_hi) by:

    t_lo = decode-trit( n mod 3 )      ; -1,0,+1 via lookup {0→-1, 1→0, 2→+1}
    t_hi = decode-trit( (n / 3) mod 3 )

  Alternate dense packing (if dictation prefers): two 2-bit trit codes per
  nibble — document choice in ASSUMPTIONS.md; default is mod-3 split above.

S0..S2 supply **local state signature** (polarity, gate bias, activation
family) for the neuromorphic cell before any graph links exist.

### 3.2 S3 — fourth variation (connectivity mode)

The fourth 4-bit section does **not** carry a third trit pair; it encodes the
**variation / wiring policy** for true neuromorphic architecture:

  Code (low 2 bits)   Mode              Behavior
  ─────────────────   ───────────────   ─────────────────────────────────────
  00                  RANDOM            Seed synapses from entropy source
                                        (PRNG or hardware jitter); no address
                                        context yet.

  01                  ADDRESS_FOLD      Fold neuron address (and neighbor
                                        address bits) into connection weights /
                                        target selection via pure math map
                                        φ(addr, addr') → influence.

  10                  CONNECTED         Follow explicit address-linked edges;
                                        only connect to neurons whose addresses
                                        appear in the fold table / link list
                                        (true neuromorphic graph).

  11                  RESERVED          User dictation TBD (continue clause)

**Progression intent (user-specified order):**

  RANDOM  →  ADDRESS_FOLD  →  CONNECTED_ADDRESSES

A developing neuron may **graduate** along this sequence as D.R.E.N.A.
recurses: early life random; maturation folds address space; stable topology
uses connected addresses only.

High 2 bits of S3: extension flags (spare until next dictation).

### 3.3 Neuron record (minimal layout)

  offset   size   field
  ──────   ────   ──────────────────────────
  +0       2      header (S0|S1|S2|S3 packed)
  +2       2      neuron id / address (edition-dependent width)
  +4       var    neural linking data (see §3.4)
  +…       var    group label ref (index into label table)
  +…       var    R.E.K.I.A. Forth cache (refined `.fs` fragment, on demand)

### 3.4 Labeled neural groups

Neurons are clustered into **neural groups** — each group carries a **label**
(human-readable name or symbolic tag). Labeling may be:

  • **Automatic** — R.E.K.I.A. `label-group` from refined Forth semantics
  • **Manual** — user assigns / renames via assistant or Forth (`group-label!`)
  • User dictation term **labilg** — treated as synonymous with **labeling**

Group record (Forth struct `group:`):

  field           description
  ─────────────   ─────────────────────────────────────────────
  group-id        stable id (edition-width address)
  label$          counted string, e.g. "memory", "dialogue", "tasks"
  member-list     head of neuron ids in this group
  link-head       index into neural linking data for inter-group edges

Groups are the unit of **assistant context** (which labeled cluster to activate)
and of **Forth vocabulary namespaces** (`GROUP-<label>/` optional prefix).

### 3.5 Neural linking data

**Neural linking data** is the typed edge store — not implicit matrix weights alone.
Stored as `link.bin` or Forth array `links,` — append-only with rewire compaction.

  Link record:
    src-id          source neuron or group-id
    dst-id          destination neuron or group-id
    link-type       intra-group | inter-group | fold-φ | random-seed
    trit-weight     (w_lo, w_hi) trit pair influence along edge
    s3-mode         wiring policy active when link was formed

D.R.E.N.A. **writes** linking data during spawn/grow/rewire; R.E.K.I.A. **reads**
it during refinement to scope `extract(K, ctx)` to the active subgraph.

Forth words (`DRENA/`):

  link!             ( src dst type w -- )       \ append link
  link@             ( link-index -- record )
  group-link!       ( group-a group-b -- )     \ inter-group bridge
  links-for-neuron  ( neuron -- addr count )

--------------------------------------------------------------------------------
4. R.E.K.I.A. — PURE MATH REFINEMENT ENGINE
--------------------------------------------------------------------------------

Full name: **Artificially Intelligent Knowledge Extraction and Refinement**

Role: Refine **on-demand intelligence** for each neuron — the knowledge payload
that D.R.E.N.A. instantiated structurally but did not fully expand.

Properties (dictated):

  • **Pure math only** at the refinement core — no mandatory neural nets.
  • Operates when a neuron is **read, fired, or queried** (lazy refinement).
  • Input: neuron header (trit pairs + variation), local graph context, and
    optional knowledge atoms (symbols, measures, proofs).
  • Output: **refined Forth** — colon definitions, constants, or `CREATE`/`DOES>`
    bodies stored in `evolve/forth/refined/<group-label>.fs`
  • **Labeling:** assign or update **labeled neural group** names from refined
    semantics (`label-group`, `group-label!`).
  • **Link-aware:** refinement uses **neural linking data** for the active
    subgraph only (neighbors + inter-group bridges).

Suggested mathematical primitives (implement as Forth vocab `REKIA/`):

  extract(K, ctx, links) → K' ⊆ K scoped by neural linking data
  refine(K', ε)          → fixed-point / contraction map; ε = tolerance
  to-forth(K', label)    → valid Forth source string or inlined words
  label-group(K', links) → suggested label$ for neural group
  prove(K', axiom)       → boolean + witness (optional formal layer)
  compose(K1, K2)        → monoid/gluing across linked groups

Refinement must be **deterministic** given (neuron, ctx, links, seed policy)
except when S3 mode is RANDOM and entropy is explicitly mixed in.

**Intelligence → Forth pipeline** (canonical):

  : rekiA-refine ( neuron ctx -- )
      neuron>group  links-for-neuron          \ labeled group + link slice
      rekiA-extract rekiA-contract
      rekiA-to-forth                         \ emit Forth; compile or save .fs
      rekiA-label-group  group-label!        \ labeling / labeled group update
  ;

Refined Forth is **loaded** (`included` / `evaluate`) into TritiumForth so
intelligence literally becomes runnable system vocabulary.

--------------------------------------------------------------------------------
5. D.R.E.N.A. — NEURAL ARCHITECTURE ENGINE
--------------------------------------------------------------------------------

Full name: **Dynamic Recursive Evolving Neural Architecture**

Role: **Construct** neurons, recurse through layers, evolve topology over time.

Properties (dictated):

  • **Dynamic** — graph size and membership change at runtime.
  • **Recursive** — self-similar sub-architectures; Forth-friendly recursion.
  • **Evolving** — S3 mode progression RANDOM → ADDRESS_FOLD → CONNECTED.
  • **Neuromorphic** — connection policy tied to address structure, not dense
    arbitrary matrices alone.
  • **Groups + links** — maintains **labeled neural groups** and **neural
    linking data** (§3.4–3.5); every spawn/grow appends link records.

Suggested Forth vocab `DRENA/`:

  drena-spawn       ( variation -- neuron )     \ allocate header + address
  drena-grow        ( parent -- child )         \ recursive expansion
  drena-rewire      ( neuron -- )               \ apply S3 policy transition
  drena-step        ( -- )                      \ one evolution tick (scheduler)
  drena-group       ( label$ -- group )         \ create labeled neural group
  drena-join        ( neuron group -- )         \ assign neuron to group

D.R.E.N.A. owns **when** a neuron advances S3 mode and **how** links are written;
R.E.K.I.A. owns **what** that neuron means — as **refined Forth** in a **labeled
group** context.

### 5b. COLLECTIVE QUEUE & ASSIMILATE CURRENCY
--------------------------------------------------------------------------------

When a refinement, puzzle slice, or graph evolution step is **not locally
computable** on the current host (CPU/RAM/time budget exceeded), the node **does
not drop the work** — it **appends to the collective queue** for distributed
processing and **earnings** tied to verified contribution.

### 5b.1 Collective queue

  Queue item fields:
    job-id            uuid
    submitter         device fingerprint + worker-key hash
    payload           neuron id | group label | puzzle fragment | Forth refine job
    local-failed-why  OOM | timeout | edition-32 limit | user opt-in offload
    proof-hash        commitment before enqueue (SHA3 or documented hash)
    status            pending | active | proved | rewarded

Forth words (`QUEUE/`):

  queue-local?        ( job -- flag )           \ can run on this host now?
  queue-enqueue!      ( job -- )                \ add to collective cue
  queue-pull          ( -- job|false )          \ worker takes next (fleet)
  queue-prove!        ( job proof -- score )    \ verifier returns contribution score

All licensed fleet members may **consume** queue jobs they can compute; **reward**
only after proof accepted against the active **Assimilate** puzzle state.

### 5b.2 Assimilate — collective neural puzzle

**Assimilate** is the global **collective neural puzzle**: a evolving target
graph + constraint set derived from aggregated:

  • neural linking data across contributors
  • R.E.K.I.A. refined Forth fragments that satisfy puzzle invariants
  • D.R.E.N.A. neuron headers that align trit-pair checksums for the current epoch

The puzzle is **not** solved by one machine — each contribution advances a shared
**solution vector** (`assimilate/puzzle.state`). When a partial merge reduces
global error metric ε, contributors earn **Assimilate currency**.

Forth words (`ASSIMILATE/`):

  assimilate-epoch      ( -- id )
  assimilate-fragment   ( group links -- frag )
  assimilate-merge!     ( frag proof -- delta-epsilon )
  assimilate-solved?    ( -- flag )               \ epoch complete → new epoch

### 5b.3 Currency units (Bitcoin : Satoshi scale)

Display name: **Assimilate**. Unit ladder mirrors **BTC : satoshi** (10⁸ subunits):

  Unit        Symbol   Value                          Notes
  ─────────   ──────   ─────────────────────────────  ─────────────────────
  Assimilate  ASIM     1 ASIM = 100,000,000 simti    Main coin (like BTC)
  simti       simti    10⁻⁸ ASIM, indivisible        Smallest unit (like satoshi)

  • All balances stored as **integer simti** (uint64); display converts to ASIM.
  • 1 ASIM = 10⁸ simti — same decimal scale as 1 BTC = 10⁸ satoshi.

Rewards are **based on contribution to the solution**, not mere queue presence:

  contribution_score = f(Δε, proof_quality, link_novelty, forth_validity)
  reward_simti       = floor( epoch_pool × score / Σ scores )   ; epoch settlement

`epoch_pool` size and issuance policy set by master system per epoch (document in
`docs/ASSIMILATE.md`; default stub pool for dev: 10⁶ simti per epoch).

### 5b.4 Wallet & earnings flow

  1. Device registers worker-key → `assimilate/wallet/<device-id>.trit`
  2. Local job fails `queue-local?` → `queue-enqueue!`
  3. Any fleet worker computes → `queue-prove!` → `assimilate-merge!`
  4. On epoch close, master or covenant contract settles simti → wallet
  5. UI shows balance in ASIM + simti; assistant command `assimilate-balance`

Anti-gaming (v0.1 minimum): duplicate proof-hash rejected; self-merge of own
fragment without Δε improvement earns zero; worker-key required for credit.
